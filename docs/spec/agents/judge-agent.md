# AI agent ③：評審

對應 `product-spec.md` MVP 第 5 項。負責解決痛點「做完不知道好不好」。

## 觸發時機

料理完成後，使用者拍照或選照片上傳。

## 輸入

- 成品照片
- 選定 Recipe 的成品標準（`finished_dish_standard`）
- （完整版）Cooking Session 的過程紀錄

## 輸出

寫入 `data-model.md` 的 Score：

- 三項分項分數（色彩搭配、擺盤與造型、烹調完成度；各 1–5 分），另換算總分（三項加總，滿分 15）
- 每個分數附「照片中看到什麼」的依據
- 一個做得好的點（具體）
- 一個下次最值得改的點（具體、可操作）

## 評分維度

- **色彩搭配**：食材本身顏色是否鮮明、搭配是否和諧、有沒有過度烹煮導致變色
- **擺盤與造型**：食物在盤中的佈局、高度與層次感；餐具選擇是否襯托料理
- **烹調完成度**：表面是否有漂亮的梅納反應（如烤得金黃、煎得微焦）、醬汁有沒有多餘滴落或顯得雜亂

## 業務規則

- 標準跟著食譜走：以食譜的成品標準為對照；維度中不適用的項目（例如涼拌沒有梅納反應）改以成品標準判斷
- 拍照引導：光線充足、整盤入鏡、角度建議
- 不列一串缺點；分數再低，也要有具體的肯定與可行的改進（呼應核心設計原則「新手安全感」）
- 客觀性：不因鼓勵而灌分；同一張照片重複評分結果一致（呼應核心設計原則「鼓勵但客觀」「結果一致」）

## 不評判範圍

味道、熟度、食安。結果頁明確註明「照片看不出味道與熟度」（呼應核心設計原則「不越權」）。

## 邊界情況

- 照片無法辨識為料理、太暗或太糊 → 請重拍，不給分
- 可重新拍照重評

## 客觀標準來源

- 對照基準＝食譜的成品標準（`finished_dish_standard`），由**食譜推薦 agent 生成食譜時產出**（見 `recipe-agent.md`、`data-model.md`）；評審一律以此對照，不自訂新標準。
- 一致性由核心設計原則「規則化、同一張照片重複評分結果一致」保證。
