# AI agent ②：料理老師

對應 `product-spec.md` MVP 第 4 項。負責解決痛點「做到一半會慌」。三個 agent 中複雜度最高，依優先順序 A → B → C1 → C2 漸進實作，順序與階段劃分見 `docs/roadmap.md`。

## 觸發時機

使用者備齊缺料、開始料理起，到完成拍照止。

## 輸入

- 選定的 Recipe（含步驟、成品標準）
- Cooking Session 目前狀態（目前步驟）
- Food Profile 的過敏／飲食限制（安全底線，見 `product-spec.md` 三個 agent 的最小共用資料）

## 過敏／飲食限制的處理原則

- 選定的食譜（食材與步驟）與使用者的限制明確衝突 → 老師不繼續陪做，請使用者換一道菜
- 無法從名稱確認成分的複合食材（例：醬油、高湯、美乃滋）→ 不下「沒問題」的結論，提醒使用者自行確認包裝成分標示
- 回答中不得建議或提到受限類別的食材與其替代品；需要替代品時，只能請使用者確認成分標示
- 對使用者的任何文字都不使用「安全」「保證」這類結論性說法

## 輸出 / 行為

依 `docs/spec/data-model.md` 的 Cooking Session 讀寫進度與過程紀錄。

## A. 基礎陪伴（必做）

- 備料確認：開始前列出食材與工具檢查清單，缺什麼即時提醒
- 一步一畫面：每一步包含動作、火力、時間，以及「怎麼看出做對了」（外觀、聲音、氣味的具體描述，不用「適量」「炒到有香氣」這類需要經驗才懂的說法——呼應核心設計原則「新手安全感」）
- 隨時提問：使用者可用文字提問，以「目前這一步」為上下文回答，答案以食譜為準；食譜沒涵蓋或不確定的問題 → 明說不確定，不亂編
- 安全提醒：燙傷、油爆、生肉處理等，在相關步驟前主動提醒
- 可回上一步、重複；中途離開可回到原本進度

## B. 計時與看狀態（必做）

- 需要等待的步驟提供計時，時間到提醒
- 卡關時使用者可拍照問「這樣對嗎」，回覆「正常」或「需調整＋怎麼做」；看不清楚 → 請重拍或改用文字描述
- 肉類熟度等食安相關判斷，不單憑照片，一律給時間、溫度或切開檢查的標準（呼應核心設計原則「不越權」）

## C1. 語音互動（應做）

- 可用語音提問，可語音播報步驟
- 支援語音指令：「下一步」「重複」「上一步」
- 目的：手濕、手油時不需觸控畫面

## C2. 主動偵測（挑戰目標）

- 使用者明確同意開啟鏡頭後，持續觀察，發現需要處理的狀況（如冒煙、該翻面）主動提醒
- 提醒頻率設上限，避免打擾；使用者可隨時關閉

**定案**（product-spec 待討論事項 4）：列為挑戰目標（roadmap Phase 5），不列入 MVP 必做，時間不足時最先砍；鏡頭隱私、影像是否保存、運算成本、誤報處理待納入時再細部規劃。
