# AI 料理助手 v2 — 功能規格

> 定版（2026/09/22）。原「待討論事項」已全數拍板，改列於文末「## 定案紀錄」；變更詳情見文末「## 變更紀錄」。

**產品名稱**：酷嗑（暖色料理品牌；App logo 為橘底白色「酷」字）。

## v1 → v2 方向轉換

一句話：v1 幫你「算」（這份食材可以吃幾天），v2 陪你「做」並給你回饋（選菜 → 陪做 → 評分）。

| 項目 | v1 | v2 |
|---|---|---|
| 目標使用者 | 單身租屋上班族（備一週便當） | 不太會煮飯的料理新手 |
| 核心問題 | 這份食材可以做幾天份、怎麼搭配 | 不知道煮什麼／做到一半會慌／做完不知道好不好 |
| 核心差異化 | 跨天規劃引擎 | 推薦 → 陪做 → 評分的閉環，三段 AI |
| 料理中 AI 問答 | 不在 MVP | 核心功能 |

## 故事主線

一個不太會煮飯的人，今天想吃櫛瓜，但不知道櫛瓜能做成什麼。他輸入「櫛瓜」，AI 推薦幾道他做得到的菜，附上難易度與時間。他挑了櫛瓜炒蛋，照缺料清單去買。

回家開火前他有點緊張，AI 料理老師一步一步陪著他：卡關時可以隨時問，也可以拍照問「這樣對嗎」。盛盤拍照後，AI 評審依標準給他一份分項成績，告訴他哪裡做得好、下次最值得改哪一點。他把這道菜存進自己的作品集，準備煮下一道。

**故事主線**：有一個想吃的食材 → 找到自己做得到、喜歡的食譜 → AI 老師陪著做 → 做完拍照給 AI 評審評分

## 核心痛點

三個痛點，剛好對應三段 AI：

| 痛點 | 說明 | 對應 AI |
|---|---|---|
| 1. 選不出來 | 有想吃的食材，卻不知道能做成什麼；搜到的食譜也看不出自己做不做得到 | ① 食譜推薦 |
| 2. 做到一半會慌 | 食譜是寫給會煮的人看的（「適量」「炒到有香氣」），新手不知道火候與時間，也沒人可以問 | ② 料理老師 |
| 3. 做完不知道好不好 | 沒有回饋就沒有進步，也沒有成就感，做完只能自己猜「應該還可以吧」 | ③ 評審 |

*目前痛點來自討論與 v1 訪談推論，前期問卷（Google 試算表）尚未整理進來，待補新手原話佐證。*

## 核心設計原則

- **避免決策疲勞**（延續 v1）：AI 優先從使用者輸入判斷意圖，不額外問可以自己判斷的問題
- **新手安全感**：不讓新手覺得自己很爛。語氣鼓勵、指令具體，不用「適量」「炒到有香氣」這類需要經驗才懂的說法，一律搭配可觀察的判斷方式
- **鼓勵但客觀**：評分要誠實，不因為想鼓勵而灌分；每個分數都要指出照片中看到的依據
- **不越權**：AI 不判斷照片看不出來的事（味道、熟度、食安）
- **結果一致**：同一道菜的難易度、預估時間，以及同一張照片的評分，每次結果一致（規則化，延續 v1「規則判斷、非 AI 自由估算」）

## 目標族群

- **主軸**：不太會煮飯、想自己下廚但怕失敗的料理新手，不限職業
- **兩種起點，同一流程支援**：手上已有食材 / 想吃某食材但還沒買

## 三個 AI 角色

| 角色 | 階段 | 職責 | 使用者感受 |
|---|---|---|---|
| ① 食譜推薦 | 做菜前 | 依食材、廚房工具、過敏限制，推薦新手做得到的菜 | 原來可以做這個 |
| ② 料理老師 | 做菜中 | 陪伴、回答問題、計時、看狀態 | 有人陪我 |
| ③ 評審 | 做菜後 | 依標準評分，給鼓勵與改進方向 | 被認真看待，知道怎麼進步 |

使用者感受為三個明確角色，語氣屬同一品牌家族；技術上三者獨立，共用「料理脈絡」（見 MVP 第 7 項，詳見 `data-model.md`）。

## MVP 功能內容

### 0. 個人化基礎資料

#### 0-1. 首次開啟 App：廚房工具（沿用 v1）

- 例如電磁爐、電子鍋、快煮鍋、氣炸鍋、烤箱、微波爐
- 作為推薦與老師的硬性篩選條件：沒有的工具，不推薦需要該工具的菜
- 首次開啟就問，之後可於設定修改

#### 0-2. 第一次生成推薦前：過敏／飲食限制、人數

- 過敏／飲食限制：安全底線，推薦前必須排除
- 預設人數（份量）
- 延後到第一次要生成推薦時才問，不擋在最前面，之後不重複問（沿用 v1）
- 飲食目標、口味偏好：移出 v2

### 1. 食材輸入

- 文字輸入想吃或手上有的食材，可一種或多種（例：櫛瓜；雞蛋、番茄）
- 不需要使用者區分「已有」或「要買」，缺的東西由缺料清單自然呈現
- 輸入內容無法辨識為食材 → 提示重新輸入
- 拍照辨識食材、標籤辨識：延後（見 `docs/out-of-scope.md`）

### 2. AI agent ①：食譜推薦

- 推薦數量 3–5 道（依可推薦結果彈性，上限 5 道）
- 每道呈現：菜名、難易度（新手／普通／需要經驗）、預估時間、所需廚房工具、缺料摘要
- 排序：新手友善優先（難易度低、時間短在前）
- 推薦前先依「廚房工具」與「過敏／飲食限制」過濾
- 難易度與預估時間依規則判斷，非 AI 自由估算（沿用 v1：步驟數、是否需提前處理、是否需憑感覺判斷、是否需特殊技巧或工具、食材數量；時間依步驟數與等待時間計算）
- 份量、搭配、步驟經合理性檢查，避免 AI 幻覺（沿用 v1）
- **每道食譜必須附「成品標準」**：成品該有的樣子（顏色、質地、外觀），供老師與評審對照
- 食譜來源：AI 生成＋規則把關；生成時以指定的台灣可靠食譜來源為根據（愛料理 iCook、Cookpad 台灣、楊桃美食網、下廚房），降低 AI 幻覺。不自建食譜資料庫
- 食材組合罕見、找不到合適菜色 → 坦白說明，並建議補一項食材或替代方向

### 3. 缺料清單

- 推薦卡片上顯示缺料摘要；選定食譜後顯示完整清單（食材、調味料、器具）
- 使用者可標記「我有這個」，缺料即時扣除
- 備齊後進入料理
- Google Maps 導航：延後

### 4. AI agent ②：料理老師（優先順序 A → B → C1 → C2）

詳見 `docs/spec/agents/cooking-teacher-agent.md`。

#### A. 基礎陪伴（必做）

- **備料確認**：開始前列出食材與工具檢查清單，缺什麼即時提醒
- **一步一畫面**：每一步包含動作、火力、時間，以及「怎麼看出做對了」（外觀、聲音、氣味的具體描述）
- **隨時提問**：使用者可用文字提問，老師以「目前這一步」為上下文回答，答案以食譜為準
- **安全提醒**：燙傷、油爆、生肉處理等，在相關步驟前主動提醒
- 可回上一步、重複；中途離開可回到原本進度
- 老師遇到食譜沒涵蓋或不確定的問題 → 明說不確定，不亂編

#### B. 計時與看狀態（必做）

- 需要等待的步驟提供計時，時間到提醒
- 卡關時使用者可拍照問「這樣對嗎」，老師回覆「正常」或「需調整＋怎麼做」；看不清楚 → 請重拍或改用文字描述
- 肉類熟度等食安相關判斷，不單憑照片，一律給時間、溫度或切開檢查的標準

#### C1. 語音互動（應做）

- 可用語音提問，老師可語音播報步驟
- 支援語音指令：「下一步」「重複」「上一步」
- 手濕、手油時不需觸控畫面

#### C2. 主動偵測（挑戰目標）

- 使用者明確同意開啟鏡頭後，老師持續觀察，發現需要處理的狀況（如冒煙、該翻面）主動提醒
- 提醒頻率設上限，避免打擾；使用者可隨時關閉
- 定案：列為挑戰目標（roadmap Phase 5），不列入 MVP 必做，時間不足時最先砍。鏡頭隱私、影像是否保存、運算成本、誤報處理待納入時再細部規劃

### 5. AI agent ③：評審

詳見 `docs/spec/agents/judge-agent.md`。

- **觸發**：料理完成後，使用者拍照或選照片上傳
- **拍照引導**：光線充足、整盤入鏡、角度建議（照片品質會影響色彩判斷）
- **評分維度（3 項）**：
  - 色彩搭配：食材本身顏色是否鮮明、搭配是否和諧、有沒有過度烹煮導致變色
  - 擺盤與造型：食物在盤中的佈局、高度與層次感；餐具選擇是否襯托料理
  - 烹調完成度：表面是否有漂亮的梅納反應（如烤得金黃、煎得微焦）、醬汁有沒有多餘滴落或顯得雜亂
- **標準跟著食譜走**：以食譜的「成品標準」為對照；維度中不適用的項目（例如涼拌沒有梅納反應）改以成品標準判斷
- **評分輸出**：
  - 三項分項分數：各 1–5 分，另換算總分（三項加總，滿分 15）
  - 每個分數附「照片中看到什麼」的依據
  - 一個做得好的點（具體）
  - 一個下次最值得改的點（具體、可操作）
  - 不列一串缺點；分數再低，也要有具體的肯定與可行的改進
- **客觀性**：不因鼓勵而灌分；同一張照片重複評分結果一致
- **不評判範圍**：味道、熟度、食安。結果頁明確註明「照片看不出味道與熟度」
- **異常處理**：照片無法辨識為料理、太暗或太糊 → 請重拍，不給分
- 可重新拍照重評

### 6. 收藏／我的作品集

- 收藏食譜：下次想再煮可以找到（沿用 v1）
- 完成的料理（成品照、分項分數、評語）存入作品集，可回顧進步
- 歷次成績回饋到推薦難易度：延後（不列入 v2 MVP）

### 7. 跨 agent 共用「料理脈絡」

詳見 `docs/spec/data-model.md`。

- 定案採「完整版」（含以下全部）：
  - 最小共用：選定的食譜、成品標準、廚房工具與過敏設定
  - 完整加項：烹飪過程紀錄（老師提醒過什麼、使用者遇到的狀況、中途照片）與歷次成績
- 例：老師知道使用者「火開太大」，評審看到焦痕時就能據此回應

## 成功指標（比賽驗證用，非商業指標）

（定案：v2 仍為比賽／Demo 導向；本表為比賽驗證用，非商業指標）

| 指標 | 驗證方式 |
|---|---|
| 新手能照著做完整道菜，不中途放棄 | 找料理新手試做，記錄完成率、卡關次數、是否需要回頭查其他資料 |
| 使用者認為推薦的菜「我做得到」 | 試做前後訪談或問卷 |
| 標示的難易度與時間，跟實際落差（沿用 v1） | 記錄實際花費時間與感受，對比標示 |
| 卡關時，老師的回答讓使用者能繼續往下做 | 觀察卡關事件，記錄解決比例 |
| 評分被認為合理、有依據 | 使用者評價，並與一般人對同一批成品照的評價對照 |
| 同一張照片重複評分，結果一致 | 同一張照片多次評分，比較落差 |
| 做完後願意再煮一道、對下廚更有信心 | 前後自評 |

## 定案紀錄（原待討論事項，2026/09/22 拍板）

1. **目標族群**：泛料理新手，不限職業（故事主線場景可保留，但定位不綁職業）。
2. **共用料理脈絡**：採**完整版**——最小共用＋過程紀錄（`session_log`）＋歷次成績。
3. **三個角色 vs 一位夥伴**：維持**三個明確角色**（食譜推薦／料理老師／評審）。
4. **老師 C2 主動偵測**：列為**挑戰目標**（roadmap Phase 5），不列 MVP 必做，時間不足最先砍；隱私／保存／成本／誤報待納入時再細規。
5. **評分制**：三項各 **1–5 分**，另換算總分（三項加總，滿分 15）。客觀標準來源＝食譜的「成品標準」（`finished_dish_standard`，由食譜推薦 agent 生成時產出），評審一律以此對照；一致性由核心原則「規則化、同一張照片結果一致」保證。
6. **食譜來源**：**AI 生成＋規則把關**，生成以指定台灣可靠來源為根據（愛料理 iCook、Cookpad 台灣、楊桃美食網、下廚房），降低幻覺；**不自建食譜庫**。推薦數量 3–5 道。
7. **歷次成績回饋推薦難易度**：**延後**，不列 v2 MVP。
8. **成品照片保存**：**保存於作品集，直到使用者刪除**，不設自動過期。
9. **前期問卷佐證**：**暫緩（follow-up）**——問卷資料尚未整理進來，不阻擋本次定版，待資料到位再補進核心痛點原話。
10. **比賽／Demo 導向**：**是**，仍為比賽／Demo 導向；Demo 最低範圍＝roadmap Phase 1–3。
